# Curio 视觉收集试运行

本轮新增独立瓷器资料功能，不接入客户资料。SQLite仍为主库，原始快照、照片、视觉观察、结构化候选和人工确认参考分别保存。

## 实际入口

审核页面左侧眼睛图标打开视觉归类资料。点击“分析下一批3件”获取一批来源并处理。处理较慢，稍后刷新查看状态和结果。打开网页本身不触发模型调用。

后台入口：

```bash
.venv/bin/python -m curio.vision run --limit 3
```

本轮尚未安装持续视觉分析定时任务，不自动处理全部库存。保存级别管理、图像相似索引、详细成交归档和跟踪频率仍为后续阶段。

## 当前处理与限制

- 获取eBay详情与最多4张照片；Kleinanzeigen尝试获取描述和图片，受页面结构与拦截限制。快照记录失败和缺失，不假装完整。
- 图片按文件内容散列去重，原文和照片留在data/porcelain；原始文件不改动。
- 已实测NVIDIA的Llama 3.2 11B视觉端点能够识别瓷器照片。其端点一次只支持一张图，因此多图生成带im1等标签的预览，原图独立保存；细节不足须留空。
- 视觉模型先输出观察，文字模型openai/gpt-oss-20b再整理成分类JSON。保留模型及用量，视觉观察可缓存；模型原始回复与未通过校验的JSON保存在candidates，不进入确认参考。
- 器型、用途、组件引用、词表、尺寸数值与证据引用经过校验；校验不能证明识别正确。所有结果仍为待核候选。
- 队列有租约、有限重试、失败时间和错误状态；完成任务不重复执行。更换分析提示版本建立新任务。
- 页面允许核对并修改JSON，再确认保存到porcelain_references。模型结果保留，不覆盖；已确认的相近器型案例作为后续整理参考，不作为新商品事实。
- 当前批次选择含瓷器或典型器型文字信号的规则候选，以减少地名带来的汽车和邮票干扰；这只是试运行范围，不宣称覆盖所有瓷器。

## 视觉风格

遵循用户提供的GoodCustomer视觉规范：陶土橙渐变、50%背景alpha、暖棕文字、线性SVG图标导航、顶部搜索、圆角及模糊层。搜索目前筛选已加载页，非全库搜索。桌面、900px、390px检查布局，不改变文字或图片整体透明度。

## 首轮结果与下一步

2026年10月15日，三件真实瓷器已形成待核候选：一套花绘摩卡/浓缩咖啡器具、一件摩卡杯碟、两件蓝色花绘瓷盘。已保存每件最多4张照片及原文，不是已鉴定档案。试跑中另有两条非瓷器干扰样本，已停止分析并记录原因。

实测暴露的错误包括：多角度拼图被当成多件商品、标签数组被写成字符串、用途代码重复主类、未注明维度的厘米值被猜成高度或直径。程序只做可审计的格式转换与保守留空，原始模型回复保留；不把这些错误变成已确认案例。主摘要由候选分类标签生成，不显示模型猜测的数量、稀有度或价值。带证据的详细字段仍需人工核对。

下一步用这三件核对字段准确性，特别是套组组件、杯形、厂标归属与品相，再增加真实样本。定时自动分析、保存规则界面和图像相似检索尚未上线。

## 首轮速度

三件成功的视觉观察加字段整理请求约73秒、102秒、81秒，按任务租约开始时间与原始模型回复落盘时间计算，不含初次资料下载及人工复核。平均约85秒，顺序处理推算35至45件每小时；初期考虑下载、限流和重试按20至30件待核候选每小时规划。仅三个样本，尚非长期吞吐测试。后续每次API调用单独记录elapsed_seconds，便于更新估算。

## 持续运行更新

2026年10月15日按用户要求启用com.curio.visual.phase1后台任务。登录后自动启动，进程退出后launchd重启；文件锁避免重复启动同一worker。每轮保存并分析一件，间隔15秒继续；已完成的商品默认不重复分析。

取资料及领取分析任务均优先选择当前状态为gone或archived的瓷器，其后处理在售候选。来源检查明确404/410或eBay缺货时标记下架，保持“成交未知”，不伪造已售。此前照片仍可用时作为补充，来源不可用不抹掉已有档案。

429后按任务重试时间暂停；401/403暂停等待修复API配置。保持每件最多三次尝试，失败记录可查看。此更新不提高原每轮20件状态检查的数量；优先级从已检测到的下架状态开始生效。电脑睡眠、关机或离线时无法继续。

## 中文审核界面

审核不再显示或要求编辑JSON。主器型、用途、造型、金饰等用中文下拉选择；图案、位置、风格、技法和颜色可多选；数量、尺寸直接填数值。可添加组件、装饰和尺寸记录，所属组件用中文名称选择。原图可展开查看。

保存时程序生成结构化记录，修改字段标记为人工参考依据并关联human_note证据。模型原始结果仍保留。空数值保持未知，不自动变为0；已确认无与未知分开。完整字段查看也改为中文标签。

## 流程持续优化

按用户要求启用本聊天每小时检查一次的维护任务。统计真实成功产出、模型耗时与失败率；正常且无明显变化时不通知。只执行可回退的小范围修复，不能降低证据要求或将未知强行归类。

2026年10月15日排查发现：多数慢速来自字段校验失败、重复调用和异常任务未释放，不是单纯视觉模型慢。已增加异常任务转待人工核对、任务耗时记录、文本整理结果缓存，优先消化现有队列再取新资料，批次间隔由15秒调整为5秒。内部组件编号可重建；无法确认关联的装饰或尺寸留空；未知标签保留原始结果且不强行映射。复用已有回复恢复了一件候选，未额外调用API。新速度须观察修复后的真实运行，不用初期理论吞吐替代实测。
