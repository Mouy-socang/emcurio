# 微信接入准备

用户指定的 SDK 已下载至 `third_party/wechat-ilink-sdk/`。上游地址、固定提交和许可证见 `third_party/manifest.json`，完整许可证随源码保留。以实际 LICENSE 的 Apache-2.0 为准；上游 README 的许可证文字可能不同。

已实现最小查询 Bot：`wechat_bot/main.go` 与 `scripts/wechat_feed.py`，已编译并生成登录二维码。扫码确认与收发实测状态以本机 `data/wechat/status.json` 为准，不在公开仓库保存登录状态。上游要求 Go 1.25，本机工具链放在 data/tools。SDK 自称官方授权，Curio 尚未独立核实该说法。

## 最小接入目标

1. 独立微信连接进程读取 Curio 已筛选候选；只向店主本人提供查询。
2. 店主扫码并先发送“看新货”，返回三件真实候选的图片、价格、依据和原链接。
3. 之后再增加稳定商品编号、审核反馈、发送去重及失败重试。
4. 定时主动通知需要验证会话时效、隔夜和重启行为，不能以收发接口存在就推定长期推送可用。

上游说明发送需要收到用户消息后的 context_token，重启后可能需要用户再次发消息。登录凭据与会话凭据不同，持久化登录不等于恢复所有会话。

## 本地数据边界

`.env`、`.weixin/`、SQLite、日志、客户资料、带聊天引文的筛选报告不提交 GitHub。登录信息放忽略目录，禁止在日志中输出。不要运行上游示例后把凭据文件加入版本控制。

Curio 的每小时采集不依赖微信程序；微信连接不可用时，采集仍应正常运行。

## 运行最小查询 Bot

安装 Go 1.25+ 和项目 Python 依赖后，在 wechat_bot 目录执行：

```sh
go mod download
go test ./...
go build -o ../data/wechat-bot .
cd ..
./data/wechat-bot --root "$PWD"
```

二维码生成到 data/wechat/login.png。请在微信确认登录，随后发“看新货”或“看候选”，每次返回3件；“下一批”继续。当前读历史客户试筛结果并用本地数据库过滤已下架、规则排除和人工已审核商品，不能声称每小时新货已完成客户匹配。回复注明试筛时间、拍卖当前价和未核验事项，只发送商品公开信息与已缓存预览图，不发客户原话或客户编号。

仅接受扫码登录所返回用户编号的私聊，其他发信人和群消息不处理。没有自动给客户发消息、定时推送、微信审核写入或模型调用。登录凭据、状态、进程锁和二维码均放忽略的 data/wechat，SDK详细日志关闭。重启后可能需要先发消息；二维码失效需重新登录。采集任务不会自动启动此Bot，也不会因Bot停止而停止。
