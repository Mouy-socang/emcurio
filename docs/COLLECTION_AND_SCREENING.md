# 采集与筛选：当前实际实现

本文描述当前代码，不把计划中的能力写成已完成。核心目标是积累可追溯的商品、知识和经营判断，减少店主手工浏览量。

## 采集

入口为 `python -m curio.curio_monitor`。`scripts/install_hourly.py` 安装本机 launchd，每3600秒运行；电脑需开机联网。桌面静默入口为 `scripts/desktop_background.py`，不打开浏览器。采集锁避免任务重叠；数据库 `collection_runs` 保存每轮状态。

eBay 使用 Browse API，市场 EBAY_DE、所在地 DE、newlyListed 排序。关键词在 `config/settings.yaml`，当前为 Meissen。初次最多1000件，后续按新上架翻页，遇本轮开始前已知 itemId 停止。增量边界保存在数据库，允许中断后重试。Kleinanzeigen 用 curl 抓搜索页，逐页检查未知编号，整页都已知才停止；置顶旧广告不会让本页后续新商品漏采。每关键词最多20页，遇拦截暂停两小时。

所有商品按平台编号入同一 `data/curio.db`，包括被规则排除的。当前没有跨平台图片去重。密钥只从本地 `.env` 读取，不写数据库或日志。

旧货状态每轮最多检查20件，最久未检查优先。明确404/410、无库存或广告删除时标记 gone，三天后 archived；不是确认 sold。失败、验证码或搜索结果缺席不作为已售证据。价格变化保留历史，固定价下降达到10%记录 price_drops。每6小时优先轮检候选、其余每日轮检尚未实现。

## 第一层：采集时规则判断

`curio/rules.py` 复用 `judge.judge()`；新商品和标价/币种变化时判断，未变化不重复判。先处理明显不相关信息，再检查文字破损/修复线索和配置规则。品牌、系列和器型识别仍是文字规则，不是鉴定。

破损默认 skip；只有配置 cheap_damaged_max 且欧元标价低于阈值时可转 probe，不能救回不相关货。`price_rules.yaml`、`slow_sellers.yaml` 当前规则列表为空，没有正式价格线。禁用了旧代码的默认硬编码价格阈值。

输出 want / probe / skip 及原因。标价 listed_price 与 total_price 分开；拍卖总价按配置手续费率计算，未知运费、税费不计，当前竞价不是成交价。want / probe 进入 screening/pipeline.py，但只有 NoopProvider，每日预算0时不调用任何 provider。

## 第二层：客户证据试筛（单次脚本）

`scripts/trial_customer_screen.py` 只读数据库快照和本地 GoodCustomer 文件，不修改生产判断。目前未接入每小时任务。

1. 用中德英别名提取 maker、form、decor、qualifiers、sizes_cm。品牌、器型、图案、等级陈述、尺寸等都只是候选。没有看图，也没有调用模型。
2. 客户正向线索仅来自客户本人“想要/喜欢”记录；排除含否定、第三方、完成线索的文字，要求可定位器型及品牌或装饰。该判断是保守正则，不理解完整上下文，可能误删，应保留审计。
3. 历史商品只使用能关联客户的资料；归属待确认、明确退款或破损等记录不用于正向订单支持。订单表记录不是核实成交，不用标准售价推断利润。
4. 双方都有品牌且不一致则不匹配。必须有共同器型，并有共同品牌或装饰。具体装饰匹配且没有已识别的未满足条件才算强匹配；客户需求还检查器型/配套集合，尺寸只做原文提取值相交，不是完整尺寸推理。
5. 按客户编号和证据类别去重，同一客户重复留言不增加独立客户数。每商品保留最多8条展示证据，完整证据总数另记。需求日期保留，但没有自动证明需求仍有效。

## 分组与排序

依次处理：已有人工判断 → 已人工审核；非 active → 已下架或非在售；规则 skip → 规则排除；有强证据 → 优先复核；有弱线索或原规则 want → 次级候选；否则暂不优先。

强匹配 specificity = 共同装饰数 × 2 + 是否有共同品牌。priority_score = 最大 specificity × 10 + 强匹配独立客户数（最多5）+ 是否有强客户需求证据 × 5。该分数是排序权重，不是购买概率或利润评分。组内先按分数，再按创建/发现时间排列。

首页最多30件，并对同一候选装饰集合与器型集合最多选3件，避免相似类型挤满页面。全部优先候选仍可查看。

## 人工反馈与局限

审核页记录 want / probe / skip、原因、心理价及当时的规则/价格快照；skip 原因必填。已有判断保存在 cases。本轮客户试筛不会覆盖它们。

反馈尚未自动变为新规则，也没有图片鉴定、真实成交价格比较、客户需求关闭或自动学习。用户需核实品相、真伪、完整配套、需求有效性和价格。试筛输出的 suggested_purchase_price 保持 null，不编造心理价。

## 字段规则入口

- `FIELD_MAPPING.md`：当前采集/试筛字段与 V2 标准的边界。
- `product-fields-v2.json`：用户规范中的75字段及逐字段填写规则。
- `瓷器字段与命名规则V2.txt`：规范正文，未公开真实订单示例。

这些文件可随代码上传；带客户引文的实际试筛 JSON、HTML、数据库和图片保留在本机忽略目录。
