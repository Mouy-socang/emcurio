用途与核心结构
本文件把当前讨论中的器型、造型、图案、风格、装饰、色地与尺寸整理为一套可维护字段，供人工录入、文字抽取、图片核对和后续匹配使用。器型树只保留“是什么、作何用途”的层级；尺寸和外观特征分别记录。
本版将讨论中的分维度方向落实为字段建议。具体英文代码、补充器型、状态语义和关联结构是本次整理方案，不代表已经部署到 Curio，也不声称是行业统一标准。

2  器型分类与用途子类

词义与歧义处理
摩卡杯碟采用 mocha。Demitasse 保留在原文或别名表中，不能仅因容量小就自动等同 mocha；只有明确用途依据时才映射。不得同时建立 mocha 与 demitasse 两个重复小杯类。
“摩卡茶壶”用途含混，记录原词，object_type = pot、object_subtype = null，并标记 needs_review。天鹅颈杯碟拆为杯碟用途与 swan_neck 柄形；不据商品昵称推断用途。
本表列出的“不设固定子类”统一写 null，状态为 not_applicable；有子类但暂不知属于哪一项，写 null，状态为 unknown。

7  鎏金细分
界面沿用用户习惯的“鎏金”；gilding 在本文件中泛指瓷器金饰，不以该字段断言具体金料或工艺。只看出金色时保留 gold_tone 色彩观察，gilding.present 仍可为 null。
gilding 字段
建议值与含义
present
true / false / null；分别为有依据确认有、确认无、未知。
types
多标签：simple_line 简单线金；wide_band 宽金带；special_border 特殊边饰；foliate 叶形；ornamental 装饰纹；complex_ornamental 复杂装饰纹；other。
extent
minimal / moderate / extensive 或 null；本条所述区域的相对覆盖程度，仅作人工描述。
band_width_mm
正数或 null；实际金带宽度，不凭照片估测。
note
string 或 null；特殊边饰形状、复杂度依据、未确认工艺等。

从用户原词到标准字段
原词
结构化表达
圈口简单鎏金
locations = [rim]；types = [simple_line]
圈口宽鎏金
locations = [rim]；types = [wide_band]
圈口特殊鎏金
locations = [rim]；types = [special_border]；note 必填具体形态

同一部位有宽金带与叶形纹可并列。complex_ornamental 可在检索时推导 ornamental，不要求人工重复录入。simple_line 与 wide_band 不设未经验证的毫米阈值；有实测值先记数值，边界案例进入复核。
一致性与品相边界
gilding.present = true 时 techniques 应包含 gilding；present = false 时 types 应为空数组，extent 与 band_width_mm 为 null 且标记 not_applicable。局部照片没看到金不能证明整件无金。
磨金、补金、重描金属于品相或修复记录，不属于 gilding.types。装饰复杂度不等于价值或稀有度。

8  色地与颜色
色地是承托图案的背景色区，图案中出现红花不等于“红色地”。同一件商品可有白瓷底、彩色外壁、另一颜色边带和金饰，需要按部位分别记录。
字段
类型与建议值
规则

布尔或 null
是否确认存在色地；自然白瓷底不自动算色地。
ground.colors
string[] 或 null
色地颜色，多色逐项记录，不使用 multiple。
ground.note
string 或 null
颜色原词、局部色区或待核说明。
body_color
组件字段，枚举或 null
瓷体外观底色：white / ivory / cream / other；不据此断定胎料。
palette_colors
string[] 或 null
本条装饰可见颜色；与色地分开。
color_mode
monochrome / polychrome / undecorated 或 null
装饰的色彩表现，不放进题材数组。

V1 颜色词表
white 白、ivory 象牙白、cream 奶油色、blue 蓝、cobalt_blue 钴蓝色调、turquoise 松石色、green 绿、yellow 黄、pink 粉、purple 紫、red 红、orange 橙、black 黑、brown 棕、grey 灰、gold_tone 金色、silver_tone 银色、other 其他。
cobalt_blue 是颜色描述，不证明使用钴颜料。只知“蓝”则填 blue，不强行细化；也不同时人工填 blue 与 cobalt_blue。不同颜色的圈口：locations = [rim] 或 [border]，再记录 ground.colors。
单色与多色的口径
本版建议 color_mode 描述该装饰单元的非金属装饰用色，不计自然白瓷底与金银色装饰；多种明确非金属色归 polychrome。同色深浅可归 monochrome。故“单色蓝绘加金”仍可记 monochrome，同时独立记录 gilding。此口径须随版本保存。
undecorated 仅用于已检查且确无装饰的范围，不能因为题材为空便推导。纯色地器物可无具象题材，但仍有色彩装饰。
未知或无色地
确认无色地时 ground.present = false、colors = []；看不到相应区域时 present = null、colors = null。多色分布位置不同就拆记录；颜色与位置不能用两组平行数组猜配。

9  尺寸字段与组件
尺寸只记录数值与测量范围，不进入器型树。统一长度单位 cm、容量 ml、重量 g；毫米或英寸原始值保留在 raw_text，转换后再存标准字段。
measurements 字段
单位与类型
测量口径
height_cm
正数或 null
实际测量高度；注明是否含盖、底座。
diameter_cm
正数或 null
圆形器物直径；口径、底径优先用专门字段。
mouth_diameter_cm / base_diameter_cm
正数或 null
口部直径／底部直径。
length_cm / width_cm
正数或 null
最长轴／与其垂直的宽；说明是否含耳柄、壶嘴。
depth_cm
正数或 null
内部深度；不能与外部高度混用。
capacity_ml / weight_g
正数或 null
容量注明满口或使用容量；重量注明组件范围。

每个测量记录的共同字段
dimensions[] 每条包含 component_id、measurements、measurement_scope、raw_text、evidence_ids。measurement_scope 用文字说明“杯体含柄不含盖”“整器含盖”等。不同口径或冲突值分为不同记录，不强行平均。
卖家写“23.5厘米”但没写维度时，raw_text 保留原文，measurements = {}，并将该字段标为 unknown 与 needs_review；不可自行填入 diameter_cm。圆盘也不能跳过这一检查。
大小与迷你
size_class 建议枚举 small / medium / large / miniature 或 null，属于可选派生字段。必须同时保存 size_rule_id、适用 object_type / subtype 和规则版本；尚无经验证阈值时保持 null。卖家写“大号”或“迷你”先保存 size_label_raw。
不得用统一高度阈值横跨杯、壶、花瓶。摩卡杯小不等于微缩器；微缩用途也不能只凭一张照片确认。本版不制定“大中小”或“迷你”的数值分界。
杯碟与套组
杯碟使用组件 cup、saucer，各自记录高度、直径或容量。不能把杯高与碟径当成一个物件的两个尺寸；同一套组中不同规格的杯需分组件记录。组件 quantity 是该组件的数量，不是订单行购买数量。
quantity 未确认时填 null。缺盖、混配和套组完整度留在相关商品事实或品相记录；只根据图片里出现几个物体，不能自动确认出售范围。

10  多标签与未知值规则
字段名采用 lower_snake_case，枚举代码用英文小写；中文作为显示标签。null 是未知数值或未知单值，[] 只表示已检查后确认没有标签。不要存中文“未知”、空字符串或 0 来代替缺失。

Other 不是缺失状态。确知某题材、造型或用途但词表无对应项时才用 other，并在 field_meta 对应路径中填写 other_text。既有已知标签也有未覆盖题材时，可以 [floral, other]。
相互排斥的候选不是多标签：杯的用途可能为茶或咖啡时，object_subtype = null；两个候选放到 field_meta.candidates 并标 needs_review。多标签只表达确实并存的内容。
字段级证据与推断
结构或字段
约定
evidence[]
id、kind、locator、raw_text；kind 用 seller_text / image / catalog / measurement / human_note。
field_meta
以 JSON Pointer 路径为键；数组位置从 0 起。保存 status、basis、evidence_ids、needs_review，必要时附 candidates、other_text、note。

seller_statement / image_observation / measurement / reference / inference；推断必须写依据，不混成卖家事实。
缺省行为
未写 field_meta 的非空字段仅表示待核录入，不能自动升级为已核实；未知字段默认 unknown。关键类型、风格、尺寸须显式给证据。

brand、pattern_id、年代、修复等字段的证据口径沿用各自业务规范。商品信息不足应产生补资料任务，不能直接推出低价值。卖家文字、图像观察与 AI 推断须可分开追溯。

13  自检结果与后续维护
自检事项
本版处理
混入器型树的尺寸
大中小、高度、直径与迷你拆到 dimensions 和 size_class；不设臆测阈值。
有耳无耳与圆方形
移至 handle_count、plan_shape、body_shape；有盖无盖移至盖设计与实物状态。
题材与风格混杂
Floral、Bird 属题材；Chinoiserie 属风格；Monochrome 属色彩；Mixed 改为多标签。
原讨论残余冲突
Dish 的 round/oval 与 Tray 的 shaped/handled 不作 subtype；Covered Bowl 的 covered 移至盖字段。
有足与高柄混淆
foot_type 与 handle_style 分开；“高柄”含混时保留原文待核。
装饰失去部位对应
采用逐条 decorations 绑定组件和位置；不使用互不关联的技法与位置数组。
宽金与复杂金饰边界
保留描述代码、备注和实测宽度；未验证前不设置自动阈值。
未知与其他混淆
unknown 是信息状态；other 是已识别但未覆盖的类别，强制说明。
来源与事实混淆
卖家陈述、图片观察、推断分别记录；不因标签完整而声称鉴定完成。
JSON 与字段一致性
示例的 JSON 语法、组件引用、字段代码和页间连续性已核对；未做生产数据覆盖率测试。

与初筛规则表的衔接
上传规则表描述的是 2026年10月6日执行快照：破损线索默认排除，器型不明转资料待补，客户匹配依赖标题中的器型、品牌、具体装饰等，价格尚未用于利润排序。本文件不改变这些规则。原对话里的新分层筛选、客户匹配加权与破损放宽仍是方案讨论，不能当作已上线行为。
新字段可给后续规则提供更精确输入，但 floral 或 blue 等宽泛标签不应自动替代“具体花样”的匹配；需要 pattern_id 或可核对的 pattern_name_raw。厂家一等二等、缺盖、磨金、修复等继续独立保存。
